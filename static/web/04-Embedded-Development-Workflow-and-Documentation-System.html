核心原则

⚖️ 文档的本质

  • 文档是沟通工具，不是目的 — 只写有人读的文档
  • 会过时的文档比没有文档更危险
  • 代码是最准确的文档 — Doxygen 注释 = SDD
  • Git 历史是最好的 ChangeLog — 不要手动维护
  • ICD 是唯一必须独立存在的设计文档（多端协作）

🔧 比文档更有效的工具

  • Git + 约定式提交 → 替代 ChangeLog.md
  • Doxygen → 替代 SDD 详细设计文档
  • cppcheck / PC-lint → 替代大量人工代码审查
  • -Wall -Werror → 0 Warning 原则强制执行
  • draw.io → 架构图比文字描述有效 10 倍
  • git tag → 版本发布即打标签

🎯 你的项目（中型）最小文档集

  • ✅ ICD 接口控制文档 — 三端联调基准
  • ✅ 架构图 + ADR — 一张图 + 关键决策
  • ✅ TestCase 测试用例集 — 发版 checklist
  • ✅ BuildGuide / README — 构建烧录步骤
  • ✅ Doxygen 注释 — 代码即设计文档
  • ✅ git tag + release notes — 版本记录
  • ❌ SRS/SDD/TestPlan — 维护成本 > 收益
