4 天课程内容（第 5 天部署 1 小时）

结构参考 03-5daysIOT2.html 的「导航 + 卡片 + 表格 + 步骤」交互讲义风格；内容对齐你仓库中的《AI生活助手4天实训教学任务》与课堂实际节奏（每天约 1 小时）。

Day1：项目启动与小程序基础

教学目标

建立「能跑起来 → 能改一点 → 能解释结构」的信心。

课堂流程（60min 建议）

  1. 10min：小程序生态与开发者工具；AppID / 测试号 / 预览。
  2. 15min：app.json 页面注册、窗口配置、目录结构。
  3. 20min：开屏/欢迎页 + 首页静态布局（view/text/image）。
  4. 15min：改标题/改颜色/改文案，真机预览与排错。

验收点

  • 能说明 app.js / app.json / app.wxss 的职责。
  • 能解释：小程序启动第一个页面由 pages 数组顺序决定。

Day2：多页面、tabBar、布局与交互

教学目标

把「一个页面」扩展成「一个小产品骨架」。

课堂流程（60min 建议）

  1. 15min：navigateTo vs switchTab；页面栈概念。
  2. 20min：配置 tabBar（图标尺寸、选中态、常见报错）。
  3. 25min：Flex 卡片布局 + rpx；做一个「功能入口宫格」首页。

验收点

  • 至少 5 个页面可跳转；tabBar 可切换。
  • 模拟器里文字不溢出、按钮可点、热区合理。

Day3：网络请求 + juhe 生活服务 + 兜底 mock

教学目标

让学生理解：接口是产品的心脏，但课堂要有「不断电」的备份方案。

课堂主线（对齐 day3-code）

  1. 封装请求：utils/request.js 统一成功/失败处理。
  2. 聚合数据：新闻头条、笑话列表；解释 error_code 与字段映射。
  3. 星座：picker + 展示多字段；说明 http/https 与域名限制可能导致回退 mock。
  4. 电商 JSON：解析复杂嵌套（cards/datasource），对应 pages/shop/shop。
  5. WebView：列表跳详情，传参 ?url=encodeURIComponent。
教师演示建议 课堂上先演示「无 Key → mock」，再演示「有 Key → 真数据」。避免一半学生卡在申请 Key。

Day4：多模型配置 + AI 对话 + 模型信息展示

教学目标

把「聊天」做成可验收的工程能力：配置、请求、观测、复盘。

课堂主线（对齐 day4-code / WXMP-new2）

  1. OpenAI 兼容格式：model / messages / temperature。
  2. 四厂商：字节豆包（火山方舟）、阿里千问（DashScope 兼容模式）、Kimi（Moonshot）、DeepSeek。
  3. 本地缓存：wx.setStorageSync 保存 Key 与模型名（豆包为 Endpoint ID）。
  4. 对话页展示：HTTP 状态码、耗时、Token usage、原始响应摘要。

课堂演示脚本（5 分钟）

我的 → 选厂商 → 粘贴 Key → 保存 → AI 页快捷提问 → 展开「本次调用信息」。

Day5：小程序部署与答辩（以 1 小时为上限）

上午/下午可拆分

  • 检查：tabBar、页面路径、关键按钮、空态/错误提示。
  • 域名：按「域名/接口」分区配置 request 合法域名、webview 业务域名。
  • 上传：开发版本 + 版本说明；体验成员扫码。
  • 答辩：3~5 分钟演示路径 + 1 段核心代码讲解（建议 utils/aiChat.js）。
部署提醒 真机预览可在开发阶段勾选「不校验合法域名」；答辩前至少演示一次「按正式规则配置域名」的流程。
